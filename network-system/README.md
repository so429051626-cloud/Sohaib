# MADIX NEXUS — نظام إدارة الشبكات

نظام ويب لإدارة شبكة إنترنت تعمل بأجهزة MikroTik: الكروت والمشتركون والمبيعات والطباعة والتقارير، مع ربط مباشر بأجهزة MikroTik عبر واجهة API.
يعمل على استضافة مشتركة عادية (PHP + MySQL) دون الحاجة إلى خادم خاص أو RADIUS.

---

## 1. المتطلبات

| العنصر | الحد الأدنى |
|---|---|
| PHP | 8.1 أو أحدث |
| إضافات PHP | `pdo_mysql`، `mbstring`، `sodium`، `json`، `zip` (للتصدير إلى Excel وتنزيل ملفات الربط) |
| قاعدة البيانات | MySQL 5.7+ أو MariaDB 10.3+ |
| أجهزة MikroTik | RouterOS 6.43+ أو 7.x، بعنوان IP عام ومنفذ API مفتوح |

## 2. التثبيت على الاستضافة (WebHostMost أو أي استضافة مشتركة)

### أ) إنشاء قاعدة البيانات
من لوحة تحكم الاستضافة → **MySQL Databases**:
1. أنشئ قاعدة بيانات جديدة.
2. أنشئ مستخدماً بكلمة مرور قوية وامنحه **كل الصلاحيات** على القاعدة.
3. احتفظ باسم القاعدة واسم المستخدم وكلمة المرور.

### ب) اختيار نسخة PHP
من **Select PHP Version** (أو ما يماثلها) اختر **8.1 أو أحدث**، وتأكد من تفعيل الإضافات المذكورة أعلاه.

### ج) رفع الملفات
1. ارفع **محتويات** مجلد `network-system` إلى مجلد الموقع (`public_html` أو مجلد النطاق الفرعي).
2. ملف `.htaccess` الموجود في الجذر يوجّه كل الطلبات إلى مجلد `public` ويحمي باقي المجلدات تلقائياً.
   - إن كانت لوحة الاستضافة تسمح بتغيير **Document Root** فاجعله يشير إلى مجلد `public` مباشرة (الخيار الأفضل).
3. تأكد أن المجلدات التالية قابلة للكتابة (الصلاحية `755` غالباً تكفي، أو `775`):
   - `config/`
   - `storage/` وكل ما بداخله
   - `public/uploads/`

### د) معالج التثبيت
1. افتح في المتصفح: `https://نطاقك/install`
2. أدخل بيانات قاعدة البيانات، واسم الشبكة، وحساب المدير.
3. بعد الانتهاء يُنشأ الملف `config/config.php` ويُقفل المعالج تلقائياً.

### هـ) شهادة SSL والرابط العام
1. فعّل **SSL** (Let's Encrypt) من لوحة الاستضافة.
2. من النظام: **الإعدادات → عام → الرابط العام للنظام** واكتب الرابط الكامل، مثل `https://net.example.com`.
   هذا الرابط تستخدمه صفحة الهوتسبوت وأجهزة MikroTik للاتصال بالنظام.

## 3. المهام الدورية (Cron)

النظام يحتاج تشغيل المهام الدورية كل دقيقة (المزامنة مع أجهزة MikroTik، إنهاء الكروت المنتهية، التنبيهات، النسخ الاحتياطي).

**الطريقة الأولى (المفضلة):** من لوحة الاستضافة → **Cron Jobs** أضف:

```
* * * * * php /home/اسم_المستخدم/public_html/cli/cron.php >/dev/null 2>&1
```

> عدّل المسار حسب مكان رفع الملفات. إن كانت الاستضافة لا تسمح بالتشغيل كل دقيقة فاختر أقل فترة متاحة (مثلاً كل 5 دقائق).

**الطريقة الثانية:** رابط الويب الموجود في **الإعدادات → المهام المجدولة**:

```
https://نطاقك/cron?key=المفتاح
```

يمكن استدعاؤه من الـ Cron بالأمر `curl -s "الرابط"` أو من أي خدمة Cron خارجية.

**احتياطي تلقائي:** يشغّل النظام المهام أيضاً عند فتح لوحة التحكم، لكن لا تعتمد عليه وحده.

## 4. تجهيز أجهزة MikroTik

### أ) فتح منفذ API
- المنفذ الافتراضي: `8728` (أو `8729` مع SSL).
- **يُنصح بشدة** بالسماح للمنفذ من عنوان IP الخاص بالاستضافة فقط:

```
/ip firewall filter add chain=input protocol=tcp dst-port=8728 src-address=IP_الاستضافة action=accept place-before=0 comment="SN panel"
/ip firewall filter add chain=input protocol=tcp dst-port=8728 action=drop comment="SN panel"
```

> عنوان IP الاستضافة يظهر في لوحة الاستضافة، أو اسأل الدعم الفني عنه.

> **مهم:** بعض الاستضافات المشتركة تمنع الاتصالات الصادرة إلى المنافذ غير المعتادة. إن ظهرت رسالة «تعذّر الاتصال» رغم صحة البيانات، فاطلب من دعم الاستضافة فتح الاتصال الصادر إلى المنفذ `8728` (أو `8729`)، أو غيّر منفذ API في جهاز MikroTik إلى منفذ تسمح به الاستضافة وعدّله في النظام.

### ب) إضافة جهاز MikroTik في النظام
1. **أجهزة MikroTik → جهاز MikroTik جديد**: الاسم، العنوان العام، المنفذ، اسم مستخدم API وكلمة المرور.
2. افتح جهاز MikroTik → تبويب **التجهيز**: انسخ السكربت والصقه في **Terminal** جهاز MikroTik (Winbox أو SSH).
   السكربت يُنشئ مستخدم API بمجموعة صلاحيات خاصة بالنظام، ويفعّل خدمة API، ويضيف النظام إلى Walled Garden.
3. اضغط **مزامنة الآن** للتأكد من الاتصال.

كرر ذلك لكل جهاز MikroTik (20–30 جهاز MikroTik أو أكثر).

## 5. ربط صفحة الهوتسبوت

النظام لا يفرض تصميماً لصفحة الدخول؛ صفحتك تبقى كما هي، وتضيف إليها ملفي الربط فقط.

1. من **ربط الهوتسبوت**: حدّد أجهزة MikroTik واضغط **نشر الملفات**، فيُنزّل كل جهاز MikroTik الملفين إلى مجلد الهوتسبوت فيه:
   - `sohaibnet.js` — مكتبة الربط
   - `sn-config.js` — إعداد جهاز MikroTik ومفتاحه
   أو نزّلهما يدوياً من زر التنزيل بجانب كل جهاز MikroTik وارفعهما إلى مجلد `hotspot` في جهاز MikroTik.
2. انسخ **كود الربط** من نفس الصفحة وضعه في:
   - `login.html`: يتحقق النظام من الكرت أو الرقم المختصر أو المشترك، ثم يُدخل المستخدم عبر جهاز MikroTik.
   - `status.html` (اختياري): يعرض الوقت والبيانات المتبقية.
3. عند تعذّر الوصول إلى النظام، تُرسل البيانات مباشرة إلى جهاز MikroTik (يمكن إيقاف ذلك من الإعدادات).

دوال المكتبة:

| الدالة | الوظيفة |
|---|---|
| `SNHotspot.login(options)` | التحقق عبر النظام ثم الدخول |
| `SNHotspot.status(options)` | معلومات الكرت أو الاشتراك للصفحة الحالية |
| `SNHotspot.info(callback)` | اسم الشبكة والباقات والأسعار |
| `SNHotspot.submitLogin(user, pass)` | دخول مباشر عبر جهاز MikroTik |
| `SNHotspot.formatBytes(n)` / `formatDuration(s)` | تنسيق الأحجام والمدد بالعربية |

## 6. النسخ الاحتياطي

- **الإعدادات → النسخ الاحتياطي**: تنزيل نسخة كاملة من قاعدة البيانات في أي وقت.
- فعّل **النسخ التلقائي اليومي** ليحتفظ النظام بنسخ في `storage/backups`.
- يُنصح أيضاً بتنزيل نسخة دورياً إلى جهازك.

## 7. ملاحظات أمنية

- غيّر كلمة مرور المدير بعد التثبيت، وأنشئ لكل موظف حساباً بصلاحيات محددة.
- لا تشارك مفتاح الـ Cron أو مفاتيح أجهزة MikroTik.
- إن ظنّ أن مفتاح جهاز MikroTik تسرّب: من تبويب **التجهيز** اضغط **تجديد المفتاح** ثم أعد نشر الملفات.
- كلمات مرور أجهزة MikroTik مخزّنة مشفّرة في قاعدة البيانات.

## 9. وضع المنصة (عدة شبكات على نفس النظام)

كل شبكة تحصل على رابط خاص بها (`https://نطاقك/اسم-الحساب`) وقاعدة بيانات مستقلة، مع لوحة مسؤول المنصة على `https://نطاقك/admin`.

### أ) المتطلبات
- خادم VPS أو استضافة تسمح لمستخدم MySQL بإنشاء قواعد بيانات (`CREATE DATABASE`).
- قاعدة بيانات للمنصة نفسها (القسم `db` في ملف الإعداد).

### ب) ملف الإعداد `config/config.php`
أضف القسم التالي إلى الملف الذي أنشأه معالج التثبيت:

```php
'platform' => [
    'enabled'   => true,
    'tenant_db' => [
        'host'   => 'localhost',
        'port'   => 3306,
        'user'   => 'mnx',          // مستخدم يملك صلاحية إنشاء قواعد البيانات
        'pass'   => '********',
        'prefix' => 'mnx_',         // بادئة قواعد بيانات الحسابات
    ],
],
```

### ج) التهيئة وحساب المسؤول
```
php cli/platform.php setup --name="صهيب قديح" --username=madix --password='كلمة_مرور_قوية'
php cli/platform.php admin --username=madix --password='كلمة_جديدة'   # تغيير كلمة المرور
php cli/platform.php tenants                                          # عرض الحسابات
```

### د) المهام الدورية في وضع المنصة
```
* * * * * php /المسار/cli/cron.php >/dev/null 2>&1
```
الأمر نفسه يشغّل مهام كل الحسابات الفعّالة بالتتابع.

### هـ) دورة حياة الحساب
- التسجيل من الصفحة الرئيسية يفتح تجربة مجانية (14 يوماً افتراضياً، قابلة للتغيير من **إعدادات المنصة**)، ويمكن اشتراط تأكيد رقم الجوال برمز SMS.
- الدخول من الصفحة الرئيسية باسم المستخدم وكلمة المرور فقط، ومن يملك أكثر من شبكة يختار الشبكة ثم يبدّل بينها من داخل النظام.
- التفعيل والتمديد والإيقاف والإلغاء من **لوحة المسؤول → الحسابات**.
- بعد انتهاء الاشتراك: **مهلة** يعمل فيها النظام كاملاً، ثم **قراءة فقط**، ثم **إيقاف** (المدد من **الفوترة**). التذكيرات تُرسل قبل الانتهاء بالأيام المحددة.
- الحساب الموقوف يعرض صفحة الإيقاف، وواجهات الـ API ترجع `403`.
- **التصاميم** و**صفحة الهبوط** من لوحة المسؤول تُطبّق على كل الحسابات والتطبيقات.

### و) لوحة المسؤول في الإصدار 2.1.0
| الصفحة | الوظيفة |
|---|---|
| **الباقات** | باقات المنصة: السعر والمدة، حدود أجهزة MikroTik والمشتركين والموظفين، الأقسام المتاحة، وحدّ الذكاء الاصطناعي الشهري |
| **الفوترة** | مدد المهلة والقراءة فقط، أيام التذكير، الحسابات البنكية، وفاتورة قابلة للطباعة لكل دفعة |
| **التحويلات** | طلبات التحويل البنكي مع صورة الإيصال: قبول يفعّل الاشتراك ويصدر الفاتورة، أو رفض مع السبب |
| **الذكاء الاصطناعي** | المزوّد Claude أو Gemini، مفتاح كلٍّ منهما (مشفّر ولا يُعرض)، النموذج، التشغيل لكل حساب، الاستهلاك والتكلفة الشهرية |
| **المساعد** و**التحليلات** | أسئلة عن المنصة، الدخل الشهري، صحة الحسابات، الحسابات المهددة بالتوقف، والتقرير الأسبوعي |
| **التذاكر** و**الإعلانات** | دعم الزبائن مع ردّ مقترح، وإعلانات تظهر داخل أنظمة الحسابات |
| **الإشعارات** | بوت تيليجرام للمسؤول: تسجيل جديد، تحويل، انتهاء اشتراك، تذكرة، التقرير الأسبوعي |
| **الحماية** | التحقق بخطوتين لدخول المسؤول مع رموز استرجاع |

وفي نظام صاحب الشبكة: **الطاقة** (جهد البطاريات والطاقة الشمسية برسوم 24 ساعة و7 أيام و30 يوماً مع حدود التنبيه)، **الانقطاعات** (سجل تلقائي ويدوي، والتعويض معطّل إلى أن يفعّله صاحب الشبكة)، **الاشتراك** (الباقة، التحويل، الفواتير)، و**الدعم**.

وفي الإصدار 2.2.0: **متابعة الكروت** (الكروت ← متابعة الكروت): البحث عن كرت وكل تفاصيله، الكروت النشطة، المنتهية مع التحديد والحذف، والأرقام المُدخلة خطأ في صفحة الهوتسبوت مع MAC وIP.

وفي الإصدار 2.2.1: **البريد الإلكتروني** (لوحة المسؤول ← البريد الإلكتروني: خادم SMTP ورسالة تجريبية ورسالة ترحيب بالبريد)، **نصوص الرسائل التلقائية** يكتبها المسؤول، **اختيار مستلمين محددين** في إرسال الرسائل، فحص اسم المستخدم أثناء الكتابة، مربعات رمز التحقق، و**قائمة جانبية جديدة** فيها بحث سريع (Ctrl+K) وأقسام قابلة للطي.

## 10. تطبيقات Android وWindows

المصدر في المجلد `network-apps/` في المستودع، ويُبنى تلقائياً عبر GitHub Actions (`.github/workflows/network-apps.yml`) عند كل تعديل، وتُنشر الملفات في صفحة **Releases**:

| الملف | النظام |
|---|---|
| `MadixNexus-2.0.0.apk` | Android 8.0 أو أحدث — تطبيق أصلي (Kotlin) |
| `MadixNexus-Setup-1.0.0.exe` | مثبّت Windows 10/11 (64-bit) |
| `MadixNexus-Portable.exe` | نسخة Windows محمولة بدون تثبيت |

### تطبيق Android
- كل الشاشات مبنية بلغة Kotlin (Jetpack Compose) ومتصلة بالنظام عبر الواجهة `/api/app/v1` برمز دخول خاص بالتطبيق.
- الدخول بحساب النظام نفسه (اسم المستخدم وكلمة المرور)، ومع وضع المنصة يُطلب اسم الحساب أيضاً.
- الصلاحيات نفسها في الموقع: كل موظف يرى ما يُسمح له به فقط.
- فتح التطبيق بالبصمة اختياري من **المزيد ← الدخول بالبصمة**.
- الأجهزة التي تستخدم التطبيق تظهر في **المزيد ← أجهزة الدخول** ويمكن إلغاء أي منها، وتغيير كلمة المرور يُخرج كل الأجهزة.
- يتطلب تحديث النظام على الخادم إلى هذه النسخة (تُنشأ الجداول الجديدة تلقائياً).

### عنوان الخادم
- العنوان الافتراضي `https://madix.kozow.com/NEXUS`، ويمكن تغييره من شاشة الدخول، أو بناء نسخة بعنوان آخر من **Actions → madix-nexus-apps → Run workflow**.

### توقيع نسخة Android
- تُوقَّع النسخ بمفتاح ثابت محفوظ في ذاكرة البناء الخاصة بالمستودع، فتُثبَّت التحديثات فوق النسخة السابقة.
- للنشر على Google Play أضف مفتاح إصدار خاص في أسرار المستودع (Settings → Secrets → Actions):
  `MADIX_KEYSTORE_B64` (ملف المفتاح بترميز Base64)، `MADIX_KEYSTORE_PASSWORD`، `MADIX_KEY_ALIAS`، `MADIX_KEY_PASSWORD`.

### تطبيق Windows
- يفتح النظام داخل نافذة التطبيق مع Windows Hello والطباعة، ويحتاج **Microsoft Edge WebView2 Runtime** (موجود مسبقاً في Windows 11 ومعظم أجهزة Windows 10).

## 11. بوت تلجرام

من القائمة الجانبية → **بوت تلجرام**:
- **بوت الإدارة:** التقارير اليومية والأسبوعية والشهرية، والتنبيهات، والأوامر للمحادثات المصرّح بها.
- **بوت الزبائن:** فحص الكرت، وربط حساب المشترك، وعرض الحالة، والتذكير قبل الانتهاء، وإشعار التجديد.
  يمكن استخدام البوت نفسه أو بوت منفصل برمز خاص.
- يعمل بنمط Webhook عند توفر HTTPS، وإلا بالاستطلاع عبر المهام الدورية.

### بوت خدمة الزبائن (لوحة المسؤول)
بوت واحد للمنصة على رقم واتساب واحد ونافذة محادثة في موقع المنصة، من **لوحة المسؤول ← التواصل ← محادثات البوت** (والإعدادات من زر «إعدادات البوت»).
- **من يراسله:** يُعرف المرسل من رقم واتساب: **صاحب شبكة** (رقم حسابه في المنصة أو رقم المالك في نظامه) يسأل عن أي شيء في النظام واشتراكه في المنصة وأرقام شبكته (المشتركون ومن ينتهي قريباً، مبيعات اليوم، أجهزة MikroTik المتوقفة، الانقطاعات) وتذاكر الدعم ويفتح تذكرة؛ **مشترك** في إحدى الشبكات يسأل عن اشتراكه وكرته وأسعار شبكته والانقطاعات؛ **زائر** يسأل عن المنصة وباقاتها، ويفحص كرتاً باسم شبكته. وأصحاب محلات **MADIX ERP** بمفتاح MADIX Cloud.
- **التحويل لشخص:** محادثة المشترك تذهب **لصاحب شبكته** في صفحة «رسائل المشتركين» في نظامه (مع تنبيه في النظام وعلى تيليجرامه)، ويرد منها فيصل الرد للمشترك على واتساب المنصة. ما عداها يذهب لفريق المنصة مع إشعار تيليجرام (لوحة المسؤول ← إشعارات تيليجرام ← «محادثة بوت تحتاج رداً»). المسؤول يرى كل المحادثات ويستطيع تحويل محادثة مشترك لصاحب شبكته أو استلامها.
- **واتساب:** من الإعدادات انسخ رابط Webhook ورمز التحقق إلى تطبيق Meta، واختر حقل `messages`، ثم ضع معرّف الرقم ورمز الوصول وسر التطبيق (تُحفظ مشفّرة). صفحة المحادثة على `/help`، ونافذة المحادثة تظهر في صفحة المنصة الرئيسية، ولها كود لأي موقع آخر.
- **التجربة:** «تجربة المساعد» في الإعدادات، مع خانة «جرّب برقم» لتجربته كصاحب شبكة أو مشترك.
- البوت يقرأ ويشرح ويحوّل فقط، ولا يكشف بيانات حساب إلا لصاحب رقمه. صلاحيتان لفريق الإدارة: `bot.chats` و`bot.manage`، ولموظفي الشبكة `subscribers.messages`.

## 12. الرسائل النصية (TweetSMS)

- من القائمة الجانبية → **الرسائل النصية → الإعدادات**: مفتاح API واسم المرسل. المفتاح يُخزَّن مشفّراً ولا يظهر في أي سجل.
- الإرسال للمشتركين حسب الحالة أو المنطقة أو الباقة، أو لأرقام تُكتب يدوياً، مع قوالب ومتغيرات (`{الاسم}`، `{تاريخ_الانتهاء}`، ...).
- رسائل تلقائية: تذكير قبل انتهاء الاشتراك، وإشعار عند التجديد.
- سجل كامل لكل رسالة وحالة كل رقم، مع إعادة الإرسال للأرقام الفاشلة.
- مسؤول المنصة يرسل لأصحاب الحسابات من **لوحة المسؤول → الرسائل النصية**.

## 13. التثبيت على خادم VPS (أمر واحد)

الملف `madix-nexus-vps.sh` يثبّت المنصة كاملة على خادم جديد: Apache وPHP وMariaDB، قاعدة البيانات، صفحة الهبوط ولوحة المسؤول، شهادة SSL مجانية، المهام الدورية كل دقيقة، نسخ احتياطي كل ليلة، الجدار الناري، محرك المراقبة والإصلاح التلقائي، ونفق أجهزة MikroTik.

- الأنظمة: **Ubuntu 24.04** (المُوصى به) أو 22.04، وDebian 12.
- يُبنى الملف تلقائياً ويُنشر في صفحة **Releases** (`.github/workflows/network-vps.yml`)، أو يدوياً: `bash network-system/deploy/vps/build.sh`.

### التثبيت
1. وجّه النطاق إلى عنوان IP الخادم (سجل `A`).
2. انسخ الملف إلى الخادم، ثم:
```
bash madix-nexus-vps.sh
```
3. أدخل النطاق والبريد واسم المسؤول وكلمة المرور. (شبكة واحدة دون المنصة: `--mode=single`.)

### التحديث
شغّل الملف الأحدث بنفس الطريقة (أو `madix update رابط-أو-ملف`): تؤخذ نسخة احتياطية، تظهر صفحة «جارٍ تحديث النظام» للحظات، وتبقى الإعدادات والبيانات والملفات المرفوعة كما هي.

### سرعة الخادم
- PHP يعمل عبر **PHP-FPM** مع Apache (`mpm_event`) و**HTTP/2**: عدد عمّال PHP محسوب من ذاكرة الخادم (9 تقريباً على خادم 1 GB) فلا تنفد الذاكرة ولا يلجأ الخادم إلى الـ swap، والملفات الثابتة لا تحجز PHP، والزائر يبقى على اتصال واحد سريع.
- الملفات ذات رقم النسخة (`?v=`) تُخزَّن في المتصفح سنة دون سؤال الخادم، وملف الأيقونات وردود JSON تُضغط.
- عند التحديث يتحوّل الخادم القديم إلى هذا الإعداد تلقائياً، وإن لم يعمل PHP-FPM يبقى PHP داخل Apache كما كان ويُكمل التحديث. `madix doctor` يعرض سطر «PHP (php8.x-fpm, HTTP/2)».
- كل صفحة (لوحة المسؤول وأنظمة الشبكات وصفحات الدخول) تقيس سرعتها من جهاز المستخدم وترسل الأزمنة فقط (بلا بيانات شخصية) إلى `storage/logs/rum.log` (حجمه محدود)، ويعرضها `madix speed`.

### أداة الإدارة `madix`
| الأمر | الوظيفة |
|---|---|
| `madix doctor` | فحص شامل مع حل لكل مشكلة |
| `madix status` | العنوان والخدمات والمساحة وآخر نسخة احتياطية |
| `madix backup` | نسخة احتياطية فورية في `/var/backups/madix` (تلقائياً كل ليلة، آخر 14 نسخة) |
| `madix restore [نسخة أو ملف]` | استعادة نسخة من الخادم أو من ملف النسخة المشفّرة، حتى على خادم جديد |
| `madix import اسم-الحساب ملف.sql.gz [config.php]` | إنشاء حساب من نسخة احتياطية لنظام سابق |
| `madix ssl نطاق بريد` | شهادة SSL وتحويل النظام إلى https |
| `madix password اسم_المستخدم` | تغيير كلمة مرور المسؤول |
| `madix tunnel` | حالة نفق أجهزة MikroTik |
| `madix logs` / `madix repair` / `madix restart` | آخر الأخطاء / إصلاح الصلاحيات / إعادة تشغيل الخدمات |
| `madix speed [ساعات]` | أين يذهب وقت فتح الصفحة (آخر 24 ساعة افتراضياً): زمن بناء كل صفحة على الخادم من سجل Apache، ثم ما قاسته هواتف المستخدمين نفسها من لمس الرابط حتى ظهور الصفحة مقسّماً إلى فتح الاتصال والخادم وتأخير الإنترنت والتنزيل وملفات التنسيق ورسم الهاتف، والجزء الأكبر منها |

### صفحة الخادم (لوحة المسؤول ← الخادم)
- المعالج والذاكرة والقرص ومدة التشغيل، حالة الخدمات، شهادة SSL، تحديثات النظام، والتنبيهات، مع تحديث كل 10 ثوانٍ.
- المحرك يعيد تشغيل أي خدمة متوقفة تلقائياً ويسجّل تنبيهاً.
- **تيليجرام**: رمز بوت ومعرّف محادثة لاستقبال تنبيهات الخادم، ونسخة احتياطية كاملة مشفّرة بكلمة مرور كل ليلة (تُفتح بالأمر `madix restore`).
- زر **نسخة احتياطية الآن**.

### لوحة المسؤول
- **الحسابات**: إنشاء، تفعيل وتجديد مع تسجيل المبلغ، تمديد التجربة، إيقاف، إلغاء، حذف، الدخول إلى نظام الحساب، كلمات المرور، حدّ أجهزة MikroTik والمشتركين لكل حساب، نسخة احتياطية للحساب.
- **استيراد حساب**: من ملف نسخة احتياطية لنظام سابق مع ملف `config.php` القديم لتبقى كلمات مرور الأجهزة صالحة.
- **المدفوعات**: سجل الدفعات والإيرادات الشهرية.

### الأنفاق الآمنة
من **أجهزة MikroTik ← الأنفاق الآمنة** يُنشأ نفق WireGuard لجهاز لا يملك عنواناً عاماً (RouterOS 7)، وتُنسخ أوامره إلى الجهاز، ثم يُضاف في النظام بعنوان النفق `10.77.x.x`. منفذ الخادم: UDP `51820`.

### نقل البيانات من الاستضافة
1. في النظام القديم: **الإعدادات ← النسخ الاحتياطي ← إنشاء نسخة الآن**، ثم تنزيل الملف، وتنزيل `config/config.php` من مدير الملفات.
2. في لوحة المسؤول على الخادم: **الحسابات ← استيراد حساب**، وارفع الملفين.
